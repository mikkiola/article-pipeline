# 0002 — Virality as success metric (superseded)

## Status
SUPERSEDED by 0004.

## Decision
Virality/engagement was adopted as Article Pipeline's success metric —
briefly, then reversed in the same session before any implementation.

## Options
A — engagement is not a metric (the prior position). B — virality is
the metric (chosen, then reversed same session).

## Chosen
B, then reversed to the core/adaptive-layer model (0004) before any
code was written.

## Why
The reversal itself is not explained beyond "replaced by 0004" — no
document records a separate justification for abandoning virality
specifically, only that 0004 superseded it. Recorded as UNKNOWN reason
for the reversal beyond "0004 arrived and replaced it."

## Constraints
None — reversed before implementation, so no constraint was ever
enforced.

## Rejected
A (engagement is not a metric) was itself already a reversal of an
earlier position before this decision was made — this ADR sits between
two other positions in the same short window.

## Consequences
None technically — reversed before reaching code. Recorded here
specifically because Immutable Lineage requires reversed decisions to
stay visible, not be deleted.

## Validation
Not applicable — decision never reached implementation.
