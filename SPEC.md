# Claim Extraction — пилот (Article Pipeline, Фаза 1)

## Overview

Первый живой компонент конвейера после Atom Selector: на 5-10 атомах из
`02_Cards/` проверить, может ли Claude Code интерактивно извлекать из одного
атома одно проверяемое утверждение (Claim) с нужными параметрами, прежде чем
проектировать Evidence Package и остальной конвейер под это.

## Goals

- [ ] Получить 5-10 РАЗНЫХ атомов через существующую ротацию `atom_selector.py`
- [ ] Для каждого атома — извлечь ровно 0 или 1 Claim (D-013: сужение объёма,
      не архитектурный принцип)
- [ ] Зафиксировать самооценённую уверенность (confidence) и маркировку
      [ФАКТ]/[ГИПОТЕЗА] на уровне каждого поля Claim
- [ ] Классифицировать неудачные/слабые случаи по категории (D-009), не только
      по проценту
- [ ] Дать Ольге материал для ручной оценки каждого Claim — это и есть
      критерий успеха пилота, формального числового порога нет
- [ ] Проверить, не сработал ли Reversal condition D-013 (систематическая
      нехватка контекста в одиночных атомах)

## Явно не входит в этот пилот

- Evidence Package, Strategy Layer, Author, Quality Gate, Platform Adapter,
  Experiment Log — следующие шаги конвейера, не эта задача.
- Подграфовая версия Claim Extraction (несколько атомов → один Claim) —
  Фаза 5+, если не сработает Reversal condition раньше.
- Числовой confidence с автокалибровкой/RL (D-008 явно отклоняет).
- Поле для ручной проверки/приёмки Claim (`reviewed`/`accepted`) — сознательно
  не добавляется на этом пилоте, проверка Ольги остаётся вне схемы.
- Причинная модель / do-calculus (D-012, далеко за горизонтом пилота).

## Tech Stack

- Python 3 (тот же стек, что `atom_selector.py`/`graph_reader.py`), стандартная
  библиотека — без новых зависимостей для этапа отбора атомов.
- Извлечение Claim из текста атома выполняется **интерактивно Claude Code**
  в сессии — отдельного API-скрипта с `ANTHROPIC_API_KEY` для этого пилота
  нет. Значит: никакого нового секрета, сетевого вызова или биллинга сверх
  обычной сессии Claude Code для самого извлечения.
- Отбор атомов (механическая часть, без LLM) — отдельный небольшой Python-
  скрипт, вызывающий `select_atom()` в цикле.

## Расположение кода

`mikkiola/article-pipeline/claim_extraction/` (пустой каркас, D-014) — не
`brain.git`. Из `brain.git` копируются (не импортируются, не симлинкаются)
`atom_selector.py` и `graph_reader.py`:

- Источник: локальный чекаут `brain.git` (путь машинно-зависим, задаётся
  через `BRAIN_REPO_DIR` — см. `graph_reader.py`), коммиты `bd7b784` (feat),
  `97b87f7` (fix), `e7fbc45` (refactor, вынос `graph_reader.py`).
- В скопированные файлы добавляется однострочный комментарий-источник
  (repo + коммиты), чтобы не забыть, что это копия и она может разойтись
  с оригиналом в `brain.git`.
- `CARDS_DIR` в скопированном `graph_reader.py` резолвится относительно
  расположения файла — значит копии в `claim_extraction/` будут смотреть на
  несуществующий `claim_extraction/02_Cards/`. **Нужно поправить `CARDS_DIR`
  на абсолютный путь к `brain/02_Cards/`** при копировании (единственное
  реальное изменение логики в копии, помимо комментария-источника).
- Состояние ротации (`atom_selector_state.json`) будет отдельным файлом рядом
  с копией в `claim_extraction/`, независимым от состояния ротации в
  `brain.git` — это ожидаемо, а не баг: два разных места запуска Article
  Pipeline пока не должны делить ротацию.

## Detailed Requirements

### Functional Requirements

**1. Отбор 5-10 уникальных атомов**

`select_atom()` в исходном виде не гарантирует уникальность между вызовами
(ротация по кластеру снаружи, `random.choice` внутри кластера — без
дедупликации). Решение: **не патчить сигнатуру `select_atom()`**, обернуть
вызовы снаружи — драйвер-скрипт вызывает `select_atom()` в цикле, копит уже
выбранные `atom_path` в set, повторные пропускает и вызывает `select_atom()`
снова, пока не наберётся 5-10 уникальных путей.

**2. Порог "нечитаемый/короткий атом — пропустить"**

Обработка ошибок чтения (`UnicodeDecodeError`/`PermissionError`/`OSError`) в
`_extract_tags()` уже есть в оригинале (`97b87f7`) и переносится как есть —
файл логируется и пропускается, весь прогон не падает.

Порог "<80 символов" из CAUSAL_MEMORY **в реальном коде `97b87f7` не найден** —
там нет проверки длины. Решение по этому пилоту: **не переносить это правило
из Drift/atom_selector в Article Pipeline без отдельного архитектурного
решения**. Если пилот покажет, что короткие/пустые атомы дают мусорные Claims —
это фиксируется как наблюдение для отдельного решения по Article Pipeline, со
своим обоснованием, не заимствованием чужого числа.

**3. Извлечение Claim (0 или 1 на атом)**

Для каждого из 5-10 атомов Claude Code читает `atom_text`, полученный от
скрипта отбора, и вручную формирует одну запись — либо Claim, либо `no_claim`.
Если в атоме заметно несколько потенциальных утверждений — выбирается самое
сильное/основное, остальные не перечисляются (сужение объёма D-013, не
架构 принцип).

**Схема записи** (одна на атом, JSON):

```json
{
  "claim_id": "20260811T153000_01",
  "extracted_at": "2026-08-11T15:30:00+03:00",
  "atom_path": "02_Cards/имя-файла-атома.md",
  "status": "claim",
  "novelty": {"value": "...", "tag": "ФАКТ"},
  "basis": {"value": "...", "tag": "ФАКТ"},
  "audience": {"value": "...", "tag": "ГИПОТЕЗА"},
  "belief_changed": {"value": "...", "tag": "ГИПОТЕЗА"},
  "desired_action": {"value": "...", "tag": "ГИПОТЕЗА"},
  "confidence": 0.6,
  "category": null,
  "reason": null
}
```

Для `status: "no_claim"` — `novelty`..`desired_action` и `confidence` равны
`null`, `category` обязателен (одно из `no_claim`/`wrong_framing`/
`bad_evidence`/`technical_failure` — D-009), `reason` — короткое текстовое
объяснение. `category` может быть непустым и при `status: "claim"` — если сам
Claim извлечён, но слабый (например, `wrong_framing`), это тоже фиксируется, а
не молчаливо проходит как обычный успешный случай.

Поля:
- `atom_path` — относительно корня `brain/` (например `02_Cards/файл.md`),
  не абсолютный путь машины — артефакт должен оставаться переносимым
  (Immutable Lineage, D-011).
- Пять содержательных полей (`novelty`, `basis`, `audience`,
  `belief_changed`, `desired_action`) — свободный текст 1-2 предложения на
  русском (язык атомов), каждое со своей меткой `[ФАКТ]`/`[ГИПОТЕЗА]`:
  `ФАКТ` — взято прямо из текста атома; `ГИПОТЕЗА` — интерпретация модели.
- `confidence` — число 0.0-1.0, самооценка Claude на весь Claim целиком (не
  отдельно по полям), формируется в момент извлечения.
- `technical_failure` как категория относится к сбоям на уровне ОТБОРА
  атома (не читается / не открылся) — такие атомы **не попадают** в
  `pilot_run_*.json` вообще, они уходят в лог отбора (см. ниже), потому что
  извлечение по ним даже не начиналось.

**4. Файлы вывода (Immutable Lineage, D-011)**

- `claim_extraction/output/pilot_run_<timestamp>.json` — массив записей
  (Claim и/или `no_claim`) за один прогон пилота. Новый прогон = новый файл,
  никогда не перезаписывает предыдущий, даже черновой.
- `claim_extraction/output/pilot_log_<timestamp>.json` — отдельно от
  `state.json` Drift (CONSTITUTION_ap, без исключений). Содержит: события
  пропуска на этапе отбора (нечитаемые файлы, пропущенные дубликаты),
  время начала/конца прогона, сводку по категориям D-009 
  (`no_claim`/`wrong_framing`/`bad_evidence`/`technical_failure` — счётчики),
  и явный флаг, сработал ли Reversal condition D-013 (см. ниже).

**5. Reversal condition D-013**

После прогона посчитать долю атомов из пилота, где `category` в
{`no_claim`, `wrong_framing`} **и причина явно указывает на нехватку
контекста** (не на что-то другое, например не bad_evidence). Если доля ≥ 40%
(например 2 из 5, 4 из 10) — записать в `pilot_log_*.json` явный флаг
`reversal_condition_triggered: true` с перечнем атомов-триггеров. Это сигнал
Ольге переходить к подграфовой версии раньше Фазы 5, не автоматическое
переключение.

**6. Порог уверенности (D-008)**

Стартовое значение — 0.5, зафиксировано как явное число на этом пилоте (не
"например"). Хранится как константа в коде отбора/сборки (не хардкод без
источника — прокомментировать ссылкой на D-008). На этом пилоте порог **не
фильтрует** вывод (все Claims, включая ниже 0.5, попадают в
`pilot_run_*.json`) — фильтрация по порогу это следующий шаг после того, как
Ольга откалибрует, что для неё значат числа confidence на реальных примерах.

### Non-Functional Requirements

1. Ни один нечитаемый/проблемный атом не должен ронять весь прогон — атом
   логируется и пропускается, прогон продолжается (тот же паттерн, что
   `97b87f7`).
2. Новый лог/состояние Article Pipeline — файл, отдельный от `state.json`
   Drift, без исключений (CONSTITUTION_ap).
3. Каждый параметр Claim маркируется `[ФАКТ]`/`[ГИПОТЕЗА]` в самой структуре
   вывода (см. схему выше), не только в свободном описании.
4. Backlink Claim → исходный атом (`atom_path`) — обязательное поле, не
   опционально.
5. Immutable Lineage — повторный прогон пилота на тех же атомах создаёт новый
   файл, не перезаписывает предыдущий результат.

## Security Considerations

Минимальный периметр: весь пилот — локальные файлы (`02_Cards/`) + сессия
Claude Code, без нового сетевого вызова, без нового секрета/API-ключа (т.к.
извлечение интерактивное, не через отдельный API-скрипт). Git-операции на
запись (push, если код пилота попадёт в удалённый репозиторий) — только через
Claude Code, не через другие инструменты.

## Test Plan

- **Технический минимум**: скрипт отбора атомов проходит весь набор 5-10 без
  необработанных падений; нечитаемые/дублирующиеся атомы пропускаются с
  логом, а не крашат прогон; `pilot_run_*.json` и `pilot_log_*.json`
  записываются корректно и не перезаписывают файлы предыдущих прогонов.
- **Приёмка по содержанию — формального числового порога нет.** Ольга вручную
  читает и оценивает каждый Claim в `pilot_run_*.json`; успех пилота
  определяется этой ручной оценкой, а не долей валидных Claims (сознательный
  выбор — см. D-009: голый процент "arbitrary threshold dressed as rigor").
  Доля `no_claim`/`wrong_framing`, связанная с нехваткой контекста, всё же
  считается отдельно и автоматически (см. Reversal condition D-013 выше), но
  это триггер для архитектурного решения, а не критерий "пилот
  провалился/удался".

  для слабых, но всё же извлечённых Claims.

  зафиксировано в канонических документах, но вытекает из языка исходного
  материала.
